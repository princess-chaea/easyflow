# EasyFlow RAG 소스 파일 정리 기준

이 폴더는 백엔드 담당자에게 전달할 RAG 원본과 검색용 변환본을 정리하는 공간입니다.

## 지금 자료를 넣는 순서

1. 아직 분류하지 않은 파일은 `00_분류대기`에 넣습니다.
2. 업무별 HWP/HWPX 원본은 `10_원본_HWP/{학교급}/{기준연도}`에 넣습니다.
3. 원본을 PDF로 변환한 검색용 파일은 `20_RAG용_PDF/{학교급}/{기준연도}`에 같은 파일명으로 넣습니다.
4. 나머지 업무별 파일을 그대로 합친 총괄본은 `90_통합본_보관_색인제외`에 넣습니다.
5. 완전 중복, 같은 연도의 초안·수정본, 폐기 문서는 `99_제외_중복_구버전`에 넣습니다.
6. `metadata_template.csv`에 자료별 학교급, 기준연도, 업무분야, 색인 여부를 기록합니다.

CSV의 기본 `school_levels`는 `all`, `early`, `secondary`를 사용합니다. `early`는 유치원·초등학교,
`secondary`는 중학교·고등학교, `all`은 학교급 공통입니다. 정말 특정 학교급에만 적용되는 예외 자료는
`kindergarten`, `elementary`, `middle`, `high`를 사용할 수 있습니다. `source_kind`는 업무별 분할본
`split`, 단순 합본 `compilation`, 공통 목차·서문 `common` 중 하나로 기록합니다.

## 핵심 원칙

- HWP/HWPX는 원본 증빙과 향후 재변환을 위해 삭제하지 않습니다.
- PDF는 페이지가 고정되어 AI 답변에 출처 페이지를 표시하기 쉬운 RAG 투입본입니다.
- 총괄본이 업무별 파일의 단순 합본이면 총괄본과 업무별 파일을 동시에 벡터화하지 않습니다.
- 이 경우 총괄본은 `index_enabled=false`, 업무별 PDF는 `index_enabled=true`로 기록합니다.
- 같은 문서를 `공통`, `유초등`, `중고등`에 복사하지 않습니다. 여러 범위에 적용되면 한 번만 저장하고 `school_levels`에 복수 값을 기록합니다.
- 파일을 저장한 날짜가 아니라 문서가 실제 적용되는 연도를 `reference_year`에 기록합니다.
- 전년도 자료도 삭제하지 말고 같은 `document_family_id`로 연결합니다. 최신 승인본을 기본 검색 대상으로 삼고 과거본은 연도 질문에만 검색되도록 합니다.

## 권장 파일명

`{기준연도}_{학교급}_{업무분야}_{자료명}_{버전}.{확장자}`

예시:

- `2026_유초등_교무학적연구학력학생부_학교업무길라잡이_최종.hwp`
- `2026_유초등_교무학적연구학력학생부_학교업무길라잡이_최종.pdf`
- `2026_중고등_안전체험정보특수과학_학교업무길라잡이_최종.pdf`

파일명에 학교명, 작성자 이름, 전화번호 등 개인정보를 넣지 않습니다.

## 업무 길라잡이 처리 기준

업무별 분할본이 총괄본과 같은 내용이면 다음과 같이 처리합니다.

| 자료 | 저장 | RAG 벡터화 | 용도 |
|---|---:|---:|---|
| 총괄 HWP/HWPX | 예 | 아니오 | 원본 대조·누락 확인 |
| 업무별 HWP/HWPX | 예 | 아니오 | 원본 증빙·재변환 |
| 업무별 PDF | 예 | 예 | 검색·페이지 인용 |
| 총괄 PDF | 선택 | 아니오 | 별도 필요가 있을 때만 보관 |

총괄본의 목차나 공통 서문에만 있는 내용이 발견되면 해당 부분만 `공통` PDF로 따로 만들고 색인합니다.

## 백엔드 담당자의 벡터화 순서

1. `metadata_template.csv`와 파일 짝을 검사합니다.
2. SHA-256으로 완전 중복을 제거합니다.
3. PDF 텍스트를 추출하고, 이미지형 PDF만 OCR 처리합니다.
4. 제목·목차·본문의 유사도를 비교해 같은 문서 계열과 버전을 묶습니다.
5. 개인정보·보안정보·저작권·최신성 검사를 수행합니다.
6. 학교관리자 승인 후 학교 범위 자료를 활성화합니다.
7. 광역 공유 요청은 서버관리자 승인 후 범위를 넓힙니다.
8. 제목과 문단 구조를 보존해 청크를 만들고 임베딩을 생성합니다.
9. 각 청크에 학교급, 기준연도, 업무분야, 원문 파일, 페이지, 승인 범위를 붙입니다.
10. 검색 품질과 출처 표시를 확인한 뒤 운영 인덱스에 활성화합니다.

권장 시작값은 문서 구조를 우선으로 나누되 본문 청크 약 500~800토큰, 겹침 80~120토큰입니다. 표는 표 제목과 열 이름이 각 청크에 포함되도록 별도로 처리합니다. 이 수치는 고정 규칙이 아니라 검색 평가 후 조정합니다.

## 폴더 구조

```text
RAG_소스파일/
├─ 00_분류대기/
├─ 10_원본_HWP/
│  ├─ 공통/2026/
│  ├─ 유초등/2026/
│  └─ 중고등/2026/
├─ 20_RAG용_PDF/
│  ├─ 공통/2026/
│  ├─ 유초등/2026/
│  └─ 중고등/2026/
├─ 90_통합본_보관_색인제외/
├─ 99_제외_중복_구버전/
└─ metadata_template.csv
```

2027년 자료가 생기면 각 학교급 아래에 `2027` 폴더만 추가합니다. 폴더 구조를 지나치게 깊게 만들지 않고 업무분야와 승인 상태는 CSV 및 백엔드 DB 메타데이터를 기준으로 관리합니다.
